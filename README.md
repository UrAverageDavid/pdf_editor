# Papertrail — PDF Notes prototype

A Flutter/Dart prototype based on [PDF_NOTES_APP_SPEC.md](PDF_NOTES_APP_SPEC.md).
The implemented slice is **open PDF → draw → autosave → close → reopen with ink aligned**,
with stroke erasing, undo/redo, navigation, and a practice document.

## Run

Install **Flutter 3.47 or newer / Dart 3.13 or newer** and the native tooling for your target.
These minimum versions match the pinned `pdfrx 2.6.5` dependency. Then, from this directory:

```sh
dart tool/bootstrap.dart
flutter analyze
flutter test
flutter run -d windows
```

Use `flutter run -d macos` on a Mac, or `flutter devices` to select an iOS/Android device.
For handwriting on Windows/Surface, use `flutter run -d windows --release`.
The default debug build adds overhead; use release for feel and profile mode
(`flutter run -d windows --profile`) when collecting performance traces.
Windows requires the Visual Studio desktop C++ toolchain, Windows SDK 10.0.22000.0 or
newer (for pen haptics declarations), and Developer Mode for the PDF
plugin's symlinks. macOS/iOS need full Xcode; Apple native PDFium dependencies also need
the package's supported CocoaPods or Swift Package Manager setup.

`bootstrap.dart` generates Windows, macOS, iOS, and Android runners in a temporary Flutter
project and copies only missing runners into this project. It leaves the application source,
tests, pubspec, and spec alone, then adds the macOS file-picker entitlement and resolves packages.
Run it once before launching. It is safe to rerun; existing runners are not regenerated.
Commit the generated runners and `pubspec.lock` after successful dependency resolution.

**Initial prototype validation (historical):** The development environment used to create this source had no Flutter
or Dart SDK, no full Xcode, and no shell network access for downloading an SDK. The application
has therefore **not been compiled, analyzed with Dart, launched, or tested on a Surface** here.
The Flutter test suite is included but must be run with the commands above. Native runners
are intentionally generated by the installed SDK, not hand-written or claimed as validated builds.
Source delimiter and relative-import checks passed. Both the bundled 3-page PDF and generated
327-page fixture were opened successfully with macOS PDFKit, including extraction of the
expected first-page text. These checks do not validate Flutter application behavior.

**Right-side writing space validation:** All 28 Flutter tests pass, including legacy-save
loading, margin persistence, alignment after expansion, erasing, undo/redo, and navigation.
Flutter analysis reports one existing `cacheExtent` deprecation in the thumbnail list.
Native app interaction and stylus hardware have not been manually validated for this feature.

**Pen and scrolling validation:** The 39-test Flutter suite passes, including adaptive
position/pressure filtering, scroll easing and momentum cancellation, retained page-image
state across scrolling, and mocked Windows haptic start/stop behavior. Analysis reports
the existing thumbnail `cacheExtent` deprecation. The Windows runner and physical pen
haptics still require a Windows build and Surface hardware validation.

## Included

- Minimal document library and recent documents.
- Native PDF picker and bundled three-page practice PDF.
- Immutable imported PDF snapshots; annotations never rewrite a PDF.
- Continuous document viewport with mixed page sizes and visible pages ±2 instantiated.
- Prioritized render queue, 64 MiB LRU image cache, and a 2-million-pixel per-page limit.
- Stylus and mouse drawing with speed-adaptive position/pressure filtering, midpoint
  curves, and normalized vector samples shared by live and saved ink.
- Continuous pen haptics on supported Windows 11 hardware while writing.
- Touch pan/pinch with release momentum, trackpad pan/zoom, eased and accelerated
  wheel/precision scrolling, Ctrl/Cmd-wheel zoom, fit width.
- Pen color and width; whole-stroke eraser, including inverted stylus when reported.
- Translucent highlighter with independent colors/widths and a dot drawing cursor.
- Optional pen shape detection for lines, single-stroke arrows, rectangles/squares,
  triangles, and circles/ellipses.
- Per-page writing space to the right: add, expand, hide/show, autosave, and undo/redo.
- Grouped erase undo/redo, with a 100-command in-memory history limit.
- Autosave after one second without input, serialized writes, checksum-verified generations, and recovery from a
  damaged newest generation. Save failures retain dirty state and show a retry banner.
- Lazy thumbnails, page count, jump-to-page, and keyboard shortcuts.
- Desktop annotation JSON backup through the document options menu. This is **not PDF export**.

## Use

Open a PDF or choose **Try the practice document**. Pen and left mouse drag draw. Touch never
creates ink: one finger pans and two fingers zoom. Select Hand to pan with a mouse.
The eraser removes whole strokes; one eraser gesture is one undo step.
Autosave waits until one second after the last input, including movement during a
stroke. Manual Save, leaving the document, and backgrounding still save immediately.

The drawing palette shows one colored icon per preset, with Fountain, Highlighter,
Fine ball, and Brush presets to start. Hover an icon to see its name, type, and size.
Tap it to select it; tap the selected icon again to open its compact settings popover.
Use **+** to copy the current pen into a new preset. Choose its name, pen type, color,
and size in the popover. Fountain, Ball, and Brush also offer pressure sensitivity
and tip sharpness. Valid edits save automatically with the document; editing or
deleting a preset leaves existing strokes unchanged.

On Windows builds, stylus contact uses a native Direct2D/DirectComposition wet-ink
preview over the document. Native pointer messages (including coalesced pen history)
update this surface directly, without a Dart round trip for every sample. The Windows
runner explicitly keeps Dart UI work on a separate thread from native input dispatch.
The preview supports the pen presets, pressure, page clipping, and translucent highlights;
mouse drawing and erasing continue through Flutter. Flutter still collects the authoritative
stroke samples for saving, undo, shape detection, and export. Native geometry follows the
same filter and nib rules, but its denser input history can produce small differences at
handoff. This is a custom native renderer, not a hosted Windows Ink `InkPresenter`.

If native graphics initialization fails or a device is lost, drawing falls back to Flutter.
The preview freezes on lift and is retired after the committed Flutter frame is submitted
and a subsequent engine frame has been drawn. Gesture tokens keep old callbacks from
clearing a newer stroke. Cancellation, focus loss, resize/DPI changes, and document disposal
clear the native surface. Other platforms retain the existing Flutter renderer.

With the Flutter renderer, a temporary predicted tip helps close the visible gap between
the pen and the ink. Steady motion projects up to 15 ms ahead, capped at 24 logical
screen pixels at every zoom. Turns, slowing, and unstable motion reduce prediction;
resting for 32 ms without another sample removes it. Predictions are replaced on
each sample and removed on lift, cancellation, or focus loss. Only actual input
is saved, recognized as shapes, erased, or used to size the writing space.

Highlighter is a pen type, so you can create several highlighter presets with their
own colors and widths. **M** selects an existing highlighter preset, or creates one
for a document that has none; **P** resumes the selected preset after Hand or Eraser.
Highlight opacity stays uniform within a stroke, even when retraced. Separate
overlapping highlights build up color. Highlights save, erase, and undo like pen ink.

Pen tips range from **0.10–8 pt**, with a slider in 0.05 pt steps. Highlighter widths
range from **6–40 pt**. Close settings with the close button, Escape, or a tap outside.
On narrow windows, swipe or scroll the palette sideways to reach every control;
settings scroll on shorter screens. Document and writing-space controls sit in the
blue top bar; undo/redo stay beside the palette.

Enable **Detect shapes (S)** to tidy pen strokes on lift. It starts off so normal
handwriting stays freehand. Draw a line, rectangle/square (including rotated ones),
triangle, or circle/ellipse in one gesture. For an arrow, draw the shaft to the tip,
draw one wing, retrace to the tip, then draw the other wing without lifting.
Close geometric outlines near their starting point. Unrecognized strokes remain
freehand; highlighter strokes are never converted. Each detected shape is one
erasable annotation and one undo step, on either the PDF or its writing space.

Pen vibration uses Windows' `InkContinuous` waveform at moderate intensity when the
pen supports it. It requires both a haptic-capable pen (such as Surface Slim Pen 2)
and compatible hardware; ordinary Surface Pens and unsupported devices continue
without vibration. See [Microsoft's pen haptics sample](https://learn.microsoft.com/en-us/samples/microsoft/windows-universal-samples/penhaptics/).
Feedback stops on lift, cancellation, leaving the drawing surface, focus loss, or
closing the document. Hand and eraser tools do not trigger writing feedback.

The scrollbar stays visible on the right to show your position in the document.
Drag its thumb with a mouse, pen, or finger, or click/tap the track to jump.
Scrollbar interaction does not create ink and is disabled during an active pen stroke.

Finger panning stays under the finger and coasts on release with a 35% velocity boost.
Faster repeated scroll signals get up to a 3× speed boost and ease to a stop. New contact, pen input, zoom,
page jumps, and focus loss stop momentum. Page images keep their widget identity
when the visible page range shifts, preventing loading flashes during scrolling.

Move the mouse cursor or hover your pen near a page's right edge, then click or tap
the **Add writing space** popup to add a blank margin to that page. Hover at the
margin's outer right edge to **Add more space**, or at the page edge to **Show writing
space** when notes are hidden. The popup stays out of the way during drawing and
touch navigation. The toolbar's **Add writing space** menu is also available.
Each manual addition provides half an original page's width. While writing in an
existing margin, it automatically grows or shrinks to fit the rightmost ink with
**40 screen pixels** of blank space, at any writing zoom. Existing notes and the
whole active stroke stay inside the margin, even when you write farther left.
Erasing also trims excess space around the remaining notes. The margin never
shrinks below half the original PDF page width, including when empty. Resizing is limited
to once per frame without moving the page under the pen, and saves and undoes
with the stroke or erase gesture. Hovering, touch navigation, and writing on the
PDF do not resize the margin. Use **Add more space to the right** for manual growth
and a view that pans to reveal it. **Fit width** fits the PDF and visible writing
areas together, or use Hand/touch to pan horizontally.

In the **Writing space** menu, choose **Blank**, **Ruled lines**, or **Grid** under
**Paper pattern**. Ruled and grid paper offer **Small (12 pt)**, **Medium (20 pt)**,
and **Large (32 pt)** spacing. Guides zoom with the page and keep their positions
as the margin grows or shrinks. These per-page settings save with your notes,
support undo/redo, and survive hiding or reopening the writing space.

**Hide writing space (keep notes)** collapses the margin without deleting it.
The toolbar shows **Notes hidden**, and the thumbnail list marks pages with writing
space. Select **Show writing space** to reopen it. Margin changes and handwriting
support undo/redo and save locally, including hidden notes. A pen or eraser gesture
ends at the divider; start a new gesture to write on the other side.

Writing space is stored alongside annotations; the source PDF stays unchanged.
Annotation JSON backups include it. PDF export of these notes is not implemented.

| Action | Shortcut |
| --- | --- |
| Pen / eraser / hand | P / E / H |
| Highlighter | M |
| Toggle pen shape detection | S |
| Undo | Ctrl/Cmd+Z |
| Redo | Ctrl/Cmd+Shift+Z; Ctrl+Y |
| Flush pending saves | Ctrl/Cmd+S |
| Open another PDF | Ctrl/Cmd+O |

Zoom percentages are relative to the original PDF's fit-width, not physical print size. Ink width is stored in
PDF display points and scales with the page. Existing PDF annotations render as part of the
background; the app does not import them as editable strokes.

## Data and recovery

Documents live below the platform application-support directory:

```text
documents/<full PDF SHA-256>/
  source.pdf                       unchanged imported snapshot
  notes-<generation>.json           committed annotation snapshot
  notes-<previous-generation>.json  recovery generations
```

Files are streamed into app storage and fingerprinted in an isolate. Importing identical
content reuses its notes. Importing changed content creates a separate document, preventing
old marks from attaching to unrelated pages. Reopening verifies the stored PDF fingerprint.
The prototype reads its private snapshot; changes to the user's external PDF are picked up
by importing it again. Import requires extra disk space and a complete copy/hash before opening.

Save payloads are encoded and written off the UI thread, flushed, then renamed to a unique
generation. The current save and two valid predecessors are retained. Incomplete `.part`
files are ignored; damaged completed saves are preserved and recovery is reported.
Do not run two copies of the app against the same library: multi-process editing is not supported.

Saves are scheduled 450 ms after a completed edit, and flushed on focus loss, document close,
and cancellable normal app exit. Force-kill, power loss, or an OS termination without a callback
can lose edits not yet committed. If saving fails, keep the document open, retry, or use the
desktop JSON backup action. Backups can be inspected/recovered manually; a backup-import UI
is not part of this prototype.

## Architecture

```text
lib/app/                         library, editor toolbar, lifecycle
lib/core/                        coordinate transforms, page layout, LRU cache
lib/features/document/           document model, repository, import/recovery
lib/features/annotations/        immutable strokes, history, autosave, painters
lib/features/pdf_viewer/         PdfEngine, pdfrx adapter, viewport, render scheduler
lib/features/export/             PdfExporter interface for the next milestone
```

Only the PDF adapter imports pdfrx. Pointer samples repaint active ink locally; committed ink
and PDF images have separate repaint boundaries. PDF and margin ink have independent change
signals, and display sizes are calculated independently of scroll offsets so moving a page
does not invalidate its retained layers. Saved ink caches ordered groups of up to 32 strokes
with a soft 4096-point limit (individual strokes remain whole for highlighter opacity).
Edits replace affected groups, zoom replaces their screen-space geometry, and unmounting a
surface releases its pictures. Thumbnail caches are separate from the main canvas.
Live pen strokes cache completed segments
and regenerate only their changing tail, preserving pressure, nib direction, and brush taper.
Highlighters append to a single path to preserve uniform translucency. Gesture caches reset
on scale/style changes and are released when the stroke ends. Background renders pause while writing;
already-running native work finishes. Queued work for disposed pages is cancelled. Images
have explicit cache/caller ownership and disposal. The cache budget excludes visible image
references and PDFium's internal memory, so it is not a total-process memory guarantee.

## Verification

The included Flutter tests cover coordinate mapping (including crop origins and rotation),
300+ page virtualization, serialization, swept eraser hit-testing, grouped history, save races,
failed-save retry, source immutability, fingerprint mismatch, generation recovery, cache eviction,
and pen/touch separation using a fake PDF engine. They do not substitute for native PDFium or
Surface hardware tests.

Create a larger manual fixture:

```sh
python3 tool/make_sample.py --pages 327 --output /tmp/papertrail-327.pdf
```

On Windows, substitute a writable Windows path for `/tmp/papertrail-327.pdf`.
Also test real scanned and complex lecture PDFs; the synthetic fixture is deliberately simple.
The bundled sample can be regenerated with `python3 tool/make_sample.py`.

On a Surface Pro 11, verify rapid handwriting, palm rest, inverted eraser, touch gestures,
immediate normal close after drawing, reopen alignment, long scrolling, and memory behavior.
Check slow diagonal lines and pressure changes at several zoom levels, quick finger
flicks, trackpad direction changes, and scrolling across page boundaries. On a supported
Surface/pen pair, check vibration during writing and that it stops on lift, Alt-Tab,
cancellation, and close. Also check a non-haptic pen. The native Windows haptics bridge
requires a Windows build and hardware validation; Flutter tests only mock its channel.
Use profile/release mode for frame-time and latency measurements.

Run `flutter test tool/ink_render_benchmark_test.dart --reporter expanded` to measure
Dart-side recording of long live strokes. This benchmark excludes GPU rendering,
display refresh, and physical pen latency. Raster comparison tests check that the
cached live renderer matches saved ink across cache boundaries and layout changes.

The predictor uses our own conservative velocity extrapolation, informed by
[Windows Ink's adaptive prediction horizon](https://learn.microsoft.com/en-us/uwp/api/windows.ui.input.inking.inkmodelerattributes.predictiontime?view=winrt-26100).
Microsoft documents a default 15 ms horizon that shrinks in less favorable conditions;
it does not publish OneNote's exact prediction algorithm in that documentation.
[Windows Ink also renders wet ink on a low-latency background thread](https://learn.microsoft.com/en-us/windows/uwp/ui-input/pen-and-stylus-interactions).
The fallback Flutter preview uses Flutter's frame pipeline; the Windows native preview
uses its own composition surface. Neither guarantees OneNote-equivalent latency. Validate quick loops,
corners, stops, and pen lift on Surface in release mode; excessive prediction can
cause temporary overshoot even though saved strokes remain accurate.

Wet-ink bridge tests cover Windows-only activation, physical-coordinate conversion,
native rejection/device failure, late replies, rapid successive strokes, disposal, and
preservation of saved samples. These tests mock the native channel. The Windows C++
renderer cannot be compiled or exercised on macOS: build with
`flutter build windows --release` on Windows, then test a physical pen at 100%, 150%,
and 200% display scaling. Check rapid dots, long strokes, brush/fountain pressure,
highlighter retracing and lift (including opacity during handoff), page boundaries,
growing writing space, zoom, Alt-Tab, window resize, and document switching. Compare
input-to-display latency with the prior Flutter path on the same device. The explicit
`RunOnSeparateThread` engine policy must be revisited if a future Flutter SDK removes it.

## Remaining MVP work

This is the first working-slice implementation, **not the complete MVP**.

1. Compile and run on Windows/Surface, validate ARM64 PDFium packaging, and fix integration issues.
2. Implement `PdfExporter` with standard Ink annotations and appearance streams; validate
   pressure, page rotation/crop boxes, output in external readers, and unchanged originals.
3. Add high-resolution tile rendering; this prototype caps whole-page resolution and may look
   soft at high zoom. The engine already exposes `renderTile`.
4. Add password entry for protected PDFs; currently the open failure is reported without
   discarding the current document. Improve missing/corrupt-file recovery UI.
5. Add touch inertia, thumbnail selection/following, persisted reading position, and richer
   stylus/platform adaptation based on actual device profiling.
6. Validate mobile file-provider behavior, orientation changes, accessibility, and native builds.

Cloud accounts, sync, OCR, lasso, and notebook hierarchy remain outside this slice.
